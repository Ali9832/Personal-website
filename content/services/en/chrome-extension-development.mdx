## When an extension is the right answer

A browser extension is the best tool when repetitive work happens inside a web panel, that service has no public API or will not grant you one, and the frequency of repetition justifies automating it.

Real examples: extracting a report from a panel that only renders HTML, auto-filling repetitive forms in an administrative system, or layering extra information onto an existing panel without touching the panel itself.

## The thing Manifest V3 changed

In Manifest V3 the background context is a service worker that shuts down when idle. Anything held in a module-level variable is gone.

```ts
// Common mistake: state in a module variable.
// let counter = 0;  ← resets when the worker shuts down.

// Correct: state in storage.
async function increment(): Promise<number> {
  const { counter = 0 } = await chrome.storage.local.get("counter");
  const next = counter + 1;
  await chrome.storage.local.set({ counter: next });
  return next;
}
```

## Permissions stay minimal

Every extra permission in `manifest.json` is both a security risk and a reason to be rejected in Web Store review. Named domains instead of `<all_urls>`. `activeTab` on click instead of standing access.

```json
{
  "manifest_version": 3,
  "permissions": ["storage", "activeTab"],
  "host_permissions": ["https://panel.example.com/*"]
}
```

This affects both how quickly review passes and what warning the user sees at install time.
