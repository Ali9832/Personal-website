## Signs you need a custom plugin

- You have installed three plugins to do one simple job, each bringing ten features you did not want.
- Your theme's `functions.php` has grown to a thousand lines and nobody will touch it.
- The plugin you depend on is unmaintained and was last updated two years ago.
- Your requirement is specific to your business and no general product exists for it.

## How the code is written

No core edits, no direct modification of other plugins, and hooks exposed so the plugin itself can be extended later:

```php
<?php
/**
 * Plugin Name: Acme Order Router
 * Requires PHP: 8.1
 */

declare( strict_types = 1 );

add_action( 'woocommerce_checkout_create_order', 'acme_assign_warehouse', 10, 2 );

function acme_assign_warehouse( WC_Order $order, array $data ): void {
    $region    = $order->get_shipping_state();
    $warehouse = acme_pick_warehouse( $region );

    // Public filter: the selection logic can be overridden later
    // without editing this file.
    $warehouse = apply_filters( 'acme_selected_warehouse', $warehouse, $order );

    $order->update_meta_data( '_acme_warehouse', $warehouse );
}
```

Two things in that short snippet matter: `declare(strict_types=1)`, because PHP's weak typing is a source of silent bugs, and `apply_filters`, because a plugin that cannot be extended gets rewritten in six months.

## Activation and data migration

Most serious plugin failures happen during activation and upgrade. Every plugin I write tracks a schema version and runs migrations step by step and reversibly — not a single `dbDelta` call and a hope.
