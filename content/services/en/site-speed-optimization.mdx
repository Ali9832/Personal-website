## Speed is a chain, not a number

When someone says "the site is slow", they almost always mean one of four things, and each has a completely different fix:

1. **The server responds late** (high TTFB) — PHP, database queries, or a missing object cache.
2. **The main content arrives late** (high LCP) — usually an unoptimised image, a font without preload, or a JavaScript slider.
3. **The page responds late to clicks** (high INP) — too much JavaScript on the main thread.
4. **Content jumps while loading** (high CLS) — images without dimensions, injected banners, fonts without a matched fallback.

What usually happens is that a plugin gets installed for problem 1 which only slightly improves problem 2. That is why measurement comes first.

## What actually gets measured

Lab data is good for diagnosis but it is not the verdict. The verdict is field data — what Google collects from your real visitors and uses in ranking. The report shows both.

| Metric | Green threshold | What it means |
| --- | --- | --- |
| LCP | under 2.5s | When the visitor feels the page has arrived |
| INP | under 200ms | How long a click takes to respond |
| CLS | under 0.1 | How much content moves under the cursor |
| TTFB | under 800ms | How long the server takes to start |

## What usually moves the needle

On WordPress sites these come up again and again:

- **`meta_query` without a supporting index** on `wp_postmeta`. Across a few thousand products a two-condition filter can take seconds.
- **Plugins that load everywhere.** A form builder injecting its CSS and JS into product pages.
- **No object cache.** Without Redis or Memcached, WordPress repeats dozens of `wp_options` queries on every request.
- **Remote fonts.** Every font from another origin is a DNS lookup and a TLS handshake before a single letter is painted.
- **Images without `width` and `height`.** The most common cause of CLS and the cheapest thing to fix.

<Callout type="tip" title="A 30-second test">
Open devtools, Network tab, and load a product page with an empty cache. If total transfer is over 3 MB or the request count is over 100, your problem is in the page itself, before any server tuning.
</Callout>
