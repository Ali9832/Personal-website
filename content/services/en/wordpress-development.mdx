## WordPress is not the problem

WordPress did not earn its reputation for being slow on its own. A clean install with a simple theme responds in a few hundred milliseconds. What makes a site heavy is usually this combination: a multipurpose theme written for every kind of site, plus a page builder, plus twenty plugins each doing a slice of what the theme should do.

I start from the opposite end: the theme contains exactly what your site needs.

## Content types, not pages

Most projects go wrong at the point where a *page* is designed rather than a *content type*. The difference shows up when you add the fiftieth item.

```php
// A defined content type with defined fields, instead of
// hand-arranging the same blocks on every page.
register_post_type( 'project', [
    'label'        => 'Projects',
    'public'       => true,
    'has_archive'  => true,
    'rewrite'      => [ 'slug' => 'projects', 'with_front' => false ],
    'supports'     => [ 'title', 'editor', 'thumbnail', 'excerpt' ],
    'show_in_rest' => true,
] );
```

Once content has structure, getting it out again — for the site, for schema, for a feed, or tomorrow for a mobile app — is a few lines of work.

## What does not go into the theme

- **jQuery**, unless a plugin genuinely requires it.
- **Remote fonts.** Fonts are self-hosted and served with `font-display: swap`.
- **A whole CSS framework.** Only what is used.
- **Tracking scripts in `wp_head`** without checking their effect on INP.

## Accessibility is part of the build

AA contrast, visible focus on every interactive element, full keyboard navigation, correct heading order. None of this costs extra time if it is done from the start. Retrofitting it later is close to a rewrite.
