## اکستنشن کِی جواب درستی است

اکستنشن مرورگر بهترین ابزار برای وضعیتی است که در آن: کاری تکراری در یک پنل وب انجام می‌شود، آن سرویس API عمومی ندارد یا به شما نمی‌دهد، و تعداد دفعات تکرار به‌قدری است که ارزش خودکارکردن دارد.

نمونه‌های واقعی: استخراج گزارش از پنلی که فقط خروجی HTML دارد، پرکردن خودکار فرم‌های تکراری در سامانه‌های اداری، یا اضافه‌کردن یک لایه اطلاعات روی پنل موجود بدون دست‌زدن به خود پنل.

## نکته‌ای که Manifest V3 عوض کرد

در Manifest V3، background یک service worker است که وقتی کاری نمی‌کند خاموش می‌شود. هر متغیری که در حافظه نگه داشته باشید، از بین می‌رود.

```ts
// اشتباه رایج: وضعیت در متغیر ماژول.
// let counter = 0;  ← با خاموش‌شدن worker صفر می‌شود.

// درست: وضعیت در storage.
async function increment(): Promise<number> {
  const { counter = 0 } = await chrome.storage.local.get("counter");
  const next = counter + 1;
  await chrome.storage.local.set({ counter: next });
  return next;
}
```

## دسترسی‌ها را کم می‌گیرم

هر مجوز اضافه در `manifest.json` هم ریسک امنیتی است و هم دلیل رد شدن در بازبینی Web Store. به‌جای `<all_urls>`، فقط دامنه‌هایی که لازم است. به‌جای دسترسی دائم، `activeTab` وقتی کاربر روی آیکون کلیک می‌کند.

```json
{
  "manifest_version": 3,
  "permissions": ["storage", "activeTab"],
  "host_permissions": ["https://panel.example.com/*"]
}
```

این تفاوت هم در سرعت تأیید Web Store اثر دارد و هم در اینکه کاربر موقع نصب چه پیامی می‌بیند.
