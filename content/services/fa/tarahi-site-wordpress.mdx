## وردپرس مشکل نیست؛ روش استفاده از آن مشکل است

وردپرس بدنامی‌اش بابت کندی را از خودش نگرفته. یک نصب تمیز وردپرس با یک قالب ساده، در چند صد میلی‌ثانیه جواب می‌دهد. چیزی که سایت را سنگین می‌کند، معمولاً این ترکیب است: یک قالب چندمنظوره که برای همه‌جور سایتی نوشته شده، به‌علاوه یک page builder، به‌علاوه بیست افزونه که هر کدام بخشی از کار قالب را انجام می‌دهند.

من از سمت مخالف شروع می‌کنم: قالب دقیقاً همان چیزی را دارد که سایت شما لازم دارد.

## ساختار محتوا، نه صفحه

بیشتر پروژه‌ها از اینجا خراب می‌شوند که «صفحه» طراحی می‌شود، نه «نوع محتوا». تفاوتش وقتی معلوم می‌شود که بخواهید محتوای پنجاهم را اضافه کنید.

```php
// یک نوع محتوای اختصاصی با فیلدهای مشخص، به‌جای
// چیدن دستی همان بلوک‌ها در هر صفحه.
register_post_type( 'project', [
    'label'        => 'پروژه‌ها',
    'public'       => true,
    'has_archive'  => true,
    'rewrite'      => [ 'slug' => 'projects', 'with_front' => false ],
    'supports'     => [ 'title', 'editor', 'thumbnail', 'excerpt' ],
    'show_in_rest' => true,
] );
```

وقتی محتوا ساختار دارد، خروجی گرفتن از آن — برای سایت، برای اسکیما، برای فید، یا فردا برای یک اپلیکیشن موبایل — کار چند خط است.

## چه چیزی در قالب نمی‌گذارم

- **jQuery** مگر اینکه افزونه‌ای واقعاً لازمش داشته باشد.
- **فونت ریموت.** فونت‌ها لوکال و با `font-display: swap` سرو می‌شوند.
- **CSS framework کامل.** فقط همان چیزی که استفاده می‌شود.
- **اسکریپت‌های تبلیغاتی و ترکینگ در `wp_head`** بدون بررسی اثرشان روی INP.

## دسترس‌پذیری هم بخشی از کار است

کنتراست در سطح AA، فوکوس قابل رؤیت روی همه عناصر تعاملی، ناوبری کامل با کیبورد و ساختار هدینگ درست. این‌ها نه هزینه اضافه‌اند و نه زمان اضافه — اگر از اول رعایت شوند. اگر بعداً بخواهید اضافه‌شان کنید، تقریباً یعنی بازنویسی.
